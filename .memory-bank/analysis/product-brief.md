# Product Brief — Somon Rent Watcher

## Metadata

- Status: draft
- Decision: proceed
- Source artifacts: operator requests of 2026-09-04; [.memory-bank/product.md](../product.md); [docs/TZ_Somon_Rent_Watcher.md](../../docs/TZ_Somon_Rent_Watcher.md)

## One-liner

Небольшой Telegram-сервис, который сам следит за свежими объявлениями аренды на Somon.tj и показывает группе только ещё не обработанные варианты, максимально близкие к общему фильтру.

## Target Users

- Настроенные администраторы, совместно управляющие одним фильтром в личном чате с ботом или целевой группе.
- Участники целевой группы, которым нужны короткие и своевременные уведомления без повторов.

## Problem

Ручной просмотр свежей выдачи занимает время. При строгом ценовом потолке подходящих объявлений может не оказаться, хотя рядом по цене есть приемлемые варианты. Текущая навигация через редактирование Telegram-сообщения также ненадёжно отображается в некоторых клиентах.

## Current Alternatives

- Вручную открывать и фильтровать выдачу Somon.tj.
- Повторно проверять старые сообщения и состояние inline-меню.
- Самостоятельно расширять ценовой диапазон и запускать новый scan.

## Value Proposition

Бот оставляет строгий фильтр основным, но в пустом цикле может показать до трёх ближайших более дорогих свежих вариантов. Управление остаётся простым и видимым в разных Telegram-клиентах.

## Product Concept

- Обычный путь первым ищет свежие объявления, полностью соответствующие фильтру.
- Только если таких объявлений не найдено, fallback рассматривает свежие варианты, которые соответствуют всем остальным условиям, стоят выше настроенного `PriceMax`, но не выше `150%` от него.
- Fallback отправляет не более трёх вариантов по возрастанию цены. Уже обработанные `seen` ID не участвуют; если свежих кандидатов нет, бот ничего не отправляет.
- Telegram admin UI работает append-only: callback подтверждается, действие выполняется, актуальное меню приходит новым сообщением; старые меню не редактируются и не удаляются.

## MVP Scope

- Price fallback внутри существующего polling pipeline без новой настройки и без миграции SQLite.
- Три ближайших по цене кандидата, прошедшие остальные существующие card/detail-фильтры.
- Существующие лимит detail-запросов, first-seen semantics, pause, backoff, recovery и delivery retry сохраняются.
- Append-only поведение всех inline callback-меню и feedback ручного scan.
- Локальная проверка, публикация commit в GitHub, затем синхронизация production checkout и обновление только Somon Rent Watcher после отдельного production preflight.

## Non-goals

- Отдельная история «показано пользователю» поверх существующего `seen_ads`.
- Backfill старых или ранее обработанных ID после изменения фильтра.
- Настраиваемый процент, количество fallback-вариантов или client detection.
- Удаление старых меню, повторное редактирование сообщений или поддержка нескольких фильтров/групп.
- Изменение чужих сервисов, контейнеров, сети, firewall, reverse proxy или базы данных на production-хосте.

## Success Metrics

- При наличии хотя бы одного свежего exact match fallback не отправляется.
- При отсутствии exact match отправляются максимум три свежих кандидата с `PriceMax < price <= 1.5 * PriceMax`, отсортированные по цене, и только после прохождения остальных фильтров.
- Один ID штатно не отправляется повторно; при отсутствии свежих кандидатов сообщений нет.
- Inline callback не вызывает `editMessageText`, а приводит к немедленному callback acknowledgement и новому сообщению с результатом/меню.
- Проектные tests, vet и production-compatible build проходят до публикации и деплоя.

## Constraints

- KISS: использовать существующие settings, `seen_ads`, scheduler, Telegram client и лимит detail-запросов; не добавлять schema/config/dependencies.
- Цена fallback рассчитывается от текущего настроенного верхнего предела `PriceMax`; без него fallback не применяется.
- Failed Telegram delivery не помечает объявление `seen`, чтобы штатный retry оставался возможен.
- Последовательность доставки: local verification → GitHub → production git sync → сборка/обновление только фактического runtime Somon Rent Watcher.
- Production-хост содержит более важные workloads; запрещены несвязанные изменения и широкие restart-команды.

## Assumptions

- «Свежий» сохраняет существующее first-seen значение: ID отсутствует в `seen_ads` на начало обработки цикла.
- «Удовлетворяет условиям, но дороже» означает нарушение только верхней границы цены; минимальная цена и все остальные фильтры обязательны.
- Если exact match найден, но Telegram delivery завершилась ошибкой, это не считается пустым поиском и fallback в этом цикле не подменяет ошибку доставки.

## Risks

- На category card часть полей может быть неизвестна; окончательное решение требует detail-filter и должно укладываться в общий request cap.
- Раннее `MarkSeen` для дорогих карточек уничтожит fallback-кандидатов до принятия решения.
- Production-документация описывает host `systemd`, тогда как оператор упомянул обновление в контейнере; фактический runtime надо определить read-only preflight непосредственно перед deployment.

## Open Questions

- Нет вопросов, блокирующих PRD: продуктовая семантика задана оператором; runtime deployment выбирается только по проверенному production state без изменения чужих workloads.

## PRD Input Summary

Сохранить текущую first-seen архитектуру и строгий фильтр как основной. Добавить ограниченный price fallback только для пустого exact-результата и перевести Telegram admin callbacks с редактирования старых сообщений на новые сообщения. Реализация не должна вводить новую схему хранения или параметры, а deployment должен быть последовательным и изолированным.
