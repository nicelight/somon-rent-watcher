# Проверка выдачи Somon по фильтрам production — 2026-09-09

Проверены те же 60 карточек из HTML выдачи, сохранённого в предыдущей диагностике,
и свежие detail-страницы всех 60 объявлений. Другие страницы поиска не обходились.
Настройки и seen IDs прочитаны из production SQLite в read-only режиме.
Парсер, модель и фильтры в рабочем дереве совпадают с установленным commit
`7f9c5f50d659` (проверен git diff соответствующих файлов).

## Результат

- 14 объявлений соответствуют фактическим фильтрам при правильном чтении цены.
- 46 отклоняются по числу активных объявлений автора (нужно строго меньше 5).
- Из 14 подходящих 11 уже в seen, 3 отсутствуют в снимке seen.
- У 11 подходящих цена карточки неверно завышена и не проходит production prefilter.
- Только 3 подходят неизменённому parser/filter pipeline; все 3 уже в seen.
- Ошибок HTTP/разбора в проверке 60 detail-страниц нет.

Фильтры: цена 3000–5200, комнаты 1/2/3/unknown, этажи
1/2/9/10/11/12/13/14+/unknown, автор <5, оба типа объявлений,
без негативных слов. Площадь бот не фильтрует.

## Метод и подтверждённый дефект

Первый изолированный Go probe использовал ParseCategory → CardMatches →
FetchDetail → AdMatches без изменений; результат 3 подходящих из 60.
Обнаружены неверные цены. Второй probe получил детали всех карточек,
повторно используя уже загруженные HTML, и прочитал цену из отдельного
DOM блока `data-component=SidebarPrice`. Только в данных диагностического
probe заменена цена; далее применён тот же AdMatches, включая seller limit.
Это диагностическое сравнение, не исправление production.

Примеры:
- 17094278 и 17075880: цена на сайте/в detail 5000, ParseCategory возвращает 65000.
- 17087959: SidebarPrice 4800, ParseCategory 74800, ParseDetail 314800.
  Название заканчивается на `д-31`, и fallback parsePrice захватывает 31 перед ценой.

Причина: ParseCategory парсит цену из текста всей карточки, а detailPrice
после отсутствующих подходящих meta/class-маркеров использует текст всей страницы.
Числовое регулярное выражение допускает пробелы и присоединяет соседние числа.
Канонический DOM блок цены текущего сайта явно не выбирается.
См. internal/somon/parser.go:parseCategoryDOM, parsePrice, detailPrice.
Минимальный маршрут исправления: извлекать цену из её собственного блока
в категории и детали; добавить регрессию на соседнее число и `д-31`.
Повторная отправка seen — отдельное поведение, не исправленное чтением цены.

Не установлено, почему каждый seen ID исторически получил эту отметку;
она сама по себе не доказывает отправку. Данные могут измениться после проверки.
Код приложения, production, Telegram и runtime state не изменялись.
