## Подтверждённые находки

### 1. Более высокий приоритет: detail parser принимает чужую страницу через fallback

Доказательства: [parser.go:323](../../internal/somon/parser.go#L323), [client.go:118](../../internal/somon/client.go#L118), [keyword_polling.go:97](../../internal/app/keyword_polling.go#L97). ParseDetail начинает с полной карточки выдачи; проверяет признаки блокировки только если ID/title отсутствуют. При обычной карточке оба уже заполнены, поэтому посторонний HTML и HTML с Access denied принимаются как успешная detail-страница. HTTP client отклоняет неуспешный статус, но при HTTP 200 передаёт тело этому parser.

Механизм независимо воспроизведён в disposable Docker copy, исходники проекта смонтированы read-only, сеть отключена. Probe TestTechDebtDetailFallback, команда CGO_ENABLED=1 go test -count=1 -v ./internal/somon -run '^TestTechDebtDetailFallback$', exit 0. Для карточки ID123, «Стол», 150 TJS оба тела — `<html><body>unrelated page</body></html>` и `<html><body>Access denied</body></html>` — вернули accepted=true, ID123, title «Стол», price150, currencyTJS. Probe существовал только внутри удалённого после выполнения контейнера. Это также ранее наблюдалось в [TASK009 acceptance evidence](../../.tasks/TASK-009-T2-FT-005-W3/TASK-009-T2-FT-005-W3-acceptance-evidence.md).

Практическое влияние: malformed/blocked HTTP200 detail может пройти delivery с данными старой listing-карточки; при Telegram success запись delivered подавляет последующую попытку. Это унаследованная слабость parser, а не новый транспорт или обход настоящих HTTP403/429. Наблюдение не доказывает частоту подобных ответов живого Somon.

Минимальное направление исправления: проверять признаки блокировки независимо от fallback и требовать подтверждение того, что detail body действительно относится к объявлению, сохраняя fallback для отдельных отсутствующих полей. Проверки должны охватить valid sparse detail, посторонний HTML и blocked HTTP200, включая сохранение retry. Сначала согласовать точный критерий валидной detail-страницы; код этим отчётом не исправлялся.

### 2. Более низкий приоритет: полный объём истории перечитывается при каждом опросе

Доказательства: [keyword_polling.go:72](../../internal/app/keyword_polling.go#L72), [keyword_search_cgo.go:151](../../internal/store/keyword_search_cgo.go#L151), [sqlite_cgo.go:111](../../internal/store/sqlite_cgo.go#L111). После получения текущих cards application вызывает KeywordAdStates(monitorID); SELECT выбирает все rows данного monitor, которые материализуются в Go map под общим db.mu. RecordKeywordAdState добавляет delivered и rejected rows; обычный poll их не удаляет. Уже существующая rental операция SeenIDs в [sqlite_cgo.go:142](../../internal/store/sqlite_cgo.go#L142) ограничивает чтение текущими IDs.

Практическое влияние: объём чтения и временной памяти зависит от всей накопленной истории H, хотя для текущего опроса нужны только C карточек. Стоимость каждого цикла O(H), и SQLite mutex удерживается на чтении всех rows. Это подтверждённая привязка runtime cost к возрасту поиска; текущая заметная задержка или порог ухудшения без benchmark/production metrics не установлены.

Минимальное направление исправления: выбирать состояния только для IDs текущей выдачи через тот же Persistence Adapter, по аналогии с SeenIDs. Доставленную историю сохранять целиком: её очистка нарушила бы принятое отсутствие повторов. Новая таблица, worker или retention policy для этого не нужны.

## Границы и неопределённость

Ожидание keyword mutation во время уже начатой Telegram отправки — принятый способ сохранить delete/send ordering; не объявлено отдельным долгом без доказанного эксплуатационного ущерба. Синтетические HTML fixtures и отсутствие fresh live keyword smoke — ограничение доказательств совместимости, а не автоматически дефект кода. Аудит не измерял production latency, объём history и частоту malformed HTTP200. Поэтому второй пункт не требует срочного переписывания; первым имеет смысл рассмотреть parser.

Создан только этот отчёт. Никаких исправлений, новых tasks, lifecycle/gate изменений или deployment не выполнено.
